# Harness 全链路审计（2026-09-27）

> 状态：迁自 Agent-Notification（2026-10-09 快照，正文未改；业务库不再留存 harness 抽取与设计文档，只留引用）。文中指向业务库专属文件的链接已改为该仓库的绝对地址。
审计方：Claude Code（设计与评审方）。标尺：[调研报告](../research/2026-09-23-agent-delivery-theory.md)第三节的 8 个环节与 3 个横切面，细到各节的节点，并对照第十七节「落地检查清单」逐条打勾。证据：`origin/main` 的 `565101e`、仓库代码与测试、GitHub 上的真实运行记录（2026-09-27 读取）。同日 Codex 在主工作目录写了一份复评（未提交），其结论本文逐条核对后并入，标为 C1–C5；本文新增的发现标为 G1–G11。

## 1. 结论

**主链已经跑通，八个环节都有落点，但只有「验证与门禁」「集成」两环形成了机器闭环；规格、规划、运行观察、度量四环主要靠约定和人。** 现在可以放心的是：Agent 自述不再算数、判定器改不了也骗不过、高风险改动必须经用户批准、历史缺陷不会悄悄回来。还不能宣称的是：「持续、稳定」有数据证明、R1 可以无人值守、执行环境彼此隔离。

交付概况（PR #7 起共 40 个）：合并 38（自动 10、人工 28），关闭 2（#16、#35）；改动行数中位 66，超过 400 行的 4 个；开 PR 到合并中位约 11 分钟；PR 上的 build 运行 64 次，失败 4 次。

| 环节 | 覆盖 | 一句话 |
|---|---|---|
| 1 需求与规格 | 部分 | 规格验收有机器映射；任务不挂规格编号，任务书自动合并不经用户审 |
| 2 上下文与知识 | 较好 | 地图短、状态在仓库；文档新鲜度无检查 |
| 3 规划与分解 | 弱 | 计划模板从未用过，预算靠自觉 |
| 4 执行环境 | 部分 | 三层护栏在；无隔离（多 Agent 共用目录）、无运行时熔断 |
| 5 验证与门禁 | 强 | verify、修复证据、base 测试、回放、变异、风险分级都在运行 |
| 6 集成与发布 | 集成强、发布未验证 | R0 自动合并与 R2+ 人审实测；非严格检查；首次发版未走过 |
| 7 运行与观察 | 弱 | 无执行轨迹留存、无停机开关、无发布后观察 |
| 8 反馈与改进 | 部分 | 缺陷能回流为测试与回放；新缺陷的回放无强制；只有一次试跑有数据 |
| 横切：安全 | 部分 | 公开仓库未开密钥扫描；同一 macOS 用户的凭据残余 |
| 横切：人的角色 | 较好 | 风险路由、自动请评审、升级包都在；评审方与设计方是同一方 |
| 横切：度量 | 弱 | 只有单 PR 计数与 trial-001 一张表 |

| 节点 | 当前实现 | 差距 | 可实现性 |

| 8.3 防作弊 | 执行方守卫禁改判定器；已有测试按 base 版本运行；修复证据要求修复前断言失败；41 个回放注入用例；6 组定向变异且得分只升不降 | **G2**：「每个修复要有回放」只对 v0.8.0 初始基线强制，新的缺陷编号（H0926-7、-8）是否补回放全靠评审方记得；base 测试不是留出测试；变异只覆盖列出的 Python 函数 | G2 小；留出测试与 Swift 变异为中到大，暂缓 |

| 8.5 可合并高于测试通过 | 架构测试、质量棘轮、用户审 R2+ | Swift 复杂度不在质量棘轮内（只统计 Python 圈复杂度与文件行数） | **G10**：小到中 |

## 4. 补齐计划
